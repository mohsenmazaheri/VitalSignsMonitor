# ۱- مقدمه

## ۱-۱ هدف این سند

این درخواست پیشنهاد (RFP) سامانه VitalSigns Monitor را توصیف می‌کند و برای طراحی، ساخت، آزمون و مستندسازی آن پیشنهاد می‌خواهد. این سند در عین حال مبنای نیازمندی‌های پروژه است: هر نیازمندی یک شناسه دارد (مثلاً `FR-ALM-03`) که طراحی، آزمون‌ها و اسناد بعدی می‌توانند به آن ارجاع دهند.

نسخه 0.2.0 نرم‌افزار از قبل وجود دارد. پیوست الف نشان می‌دهد این نسخه کدام نیازمندی‌ها را پوشش می‌دهد و کدام‌ها برنامه‌ریزی شده‌اند.

## ۱-۲ پیشینه

مانیتور کنار تخت بیمار داده‌ها را از دستگاه‌های اندازه‌گیری (تقویت‌کننده ECG، پالس‌اکسیمتر) از طریق درگاه سریال یا شبکه دریافت می‌کند. نرم‌افزار باید یک جریان پیوسته باینری را بخواند، خطاهای انتقال را تشخیص دهد و از آن‌ها عبور کند، موج‌ها و اعداد را بدون تأخیر نمایش دهد و هشدارها را با اولویت روشن اعلام کند. اگر ارتباط قطع شود، مانیتور باید قطع ارتباط را اعلام کند و مقادیر قدیمی را نشان ندهد.

VitalSigns Monitor مدلی واقع‌گرایانه ولی غیربالینی از چنین سامانه‌ای است. این سامانه از یک برنامه مانیتور و یک شبیه‌ساز بیمار تشکیل شده که نقش دستگاه کنار تخت را بازی می‌کند.

## ۱-۳ تذکر مهم

- سامانه **فقط داده مصنوعی** پردازش می‌کند. هیچ داده واقعی بیمار نباید ذخیره، پردازش یا ارسال شود.
- سامانه **وسیله پزشکی نیست** و هیچ ادعایی درباره انطباق با استانداردهای پزشکی ندارد.
- هر جا به استانداردی اشاره شده (IEC 60601-1-8، IEC 62304، ISO 14971)، کار فقط «به سبک» آن استاندارد و به‌عنوان تمرین آموزشی انجام می‌شود.

## ۱-۴ تعاریف و اختصارات

| اصطلاح | معنی |
|---|---|
| ECG | نوار قلب؛ فعالیت الکتریکی قلب که به‌صورت موج نمایش داده می‌شود |
| HR | ضربان قلب بر حسب ضربه در دقیقه (bpm) |
| SpO2 | درصد اشباع اکسیژن خون محیطی |
| فریم (Frame) | یک واحد پروتکل: بایت‌های همگام‌سازی، سرآیند، داده و CRC |
| CRC | کد بررسی افزونگی چرخه‌ای؛ در این پروژه CRC-16/CCITT-FALSE |
| پرش شماره ترتیب | جهش در شماره ترتیب فریم‌ها که یعنی فریم‌هایی گم شده‌اند |
| زمان‌سنج نگهبان (Watchdog) | زمان‌سنجی که اگر ۳ ثانیه فریم معتبری نرسد، قطع ارتباط را اعلام می‌کند |
| ترابر (Transport) | اتصال مانیتور به دستگاه (TCP یا درگاه سریال) |
| خروجی (Sink) | خروجی شبیه‌ساز (سرور TCP یا درگاه سریال) |
| سناریو | توالی زمان‌بندی‌شده‌ای از وضعیت‌های بیمار در شبیه‌ساز |
| MVVM | الگوی Model-View-ViewModel که بین C++ و QML به کار رفته است |

# ۲- نمای کلی پروژه

## ۲-۱ اهداف

- ساخت یک مانیتور رومیزی که موج زنده ECG، ضربان قلب و SpO2 را از دستگاهی که از طریق TCP یا درگاه سریال وصل است نمایش دهد.
- تشخیص مشکلات انتقال (بایت خراب، فریم گم‌شده، ارتباط ساکت) و گزارش صادقانه آن‌ها.
- اعلام هشدارهای فیزیولوژیک و فنی در سه سطح اولویت.
- فراهم کردن شبیه‌ساز بیمار که سیگنال مصنوعی تولید کند و بتواند خطا تزریق کند، تا هر رفتار مانیتور بدون سخت‌افزار قابل تکرار باشد.
- نشان دادن یک فرایند حرفه‌ای توسعه نرم‌افزار: معماری لایه‌ای، طراحی SOLID، آزمون واحد، ساخت بدون هشدار کامپایلر و مستندات کامل.

## ۲-۲ محدوده

در محدوده پروژه:

- برنامه مانیتور (رومیزی ویندوز و لینوکس).
- شبیه‌ساز بیمار با پنل جلوی شبیه به سخت‌افزار، و شبیه‌ساز خط فرمان.
- پروتکل باینری دستگاه با CRC و شماره ترتیب.
- موتور هشدار، آزمون‌های واحد، سامانه ساخت و مستندات به دو زبان انگلیسی و فارسی.

خارج از محدوده:

- سخت‌افزار واقعی اندازه‌گیری و داده واقعی بیمار.
- اعتبارسنجی بالینی، گواهی‌نامه یا ارائه مدارک به مراجع قانونی.
- ایستگاه مرکزی، پایگاه داده بیماران، توزیع داده بین چند مانیتور (هر پنجره مانیتور یک دستگاه).

# ۳- بستر سامانه

شبیه‌ساز بیمار سیگنال‌های یک بیمار مصنوعی را تولید می‌کند و آن‌ها را به‌صورت فریم‌های پروتکل می‌فرستد. مانیتور فریم‌ها را دریافت و بررسی می‌کند و نتیجه را نمایش می‌دهد.

```
+----------------------------+   TCP 127.0.0.1:5555    +-----------------------------+
|  VitalSignsPatientSimulator | ---------------------> |  VitalSignsMonitor          |
|  (or VitalSignsSimulator)   |   or serial COMx       |  ECG sweep, HR, SpO2,       |
|  synthetic patient,         |   (8N1, 115200 baud)   |  alarms, link statistics    |
|  scenarios, fault injection |                        |                             |
+----------------------------+                         +-----------------------------+
```

# ۸- محتوای پیشنهاد

پیشنهاد باید شامل موارد زیر باشد:

1. برداشت پیشنهاددهنده از نیازمندی‌ها، همراه با پرسش‌ها و فرض‌ها.
2. رویکرد فنی: معماری، مدل رشته‌ها، پردازش پروتکل و طراحی هشدار.
3. رویکرد آزمون: چه چیزی خودکار و چه چیزی دستی آزموده می‌شود و خطاها چگونه بازتولید می‌شوند.
4. برنامه کار با مراحلی منطبق بر بخش ۷.
5. ریسک‌ها و راه‌های کاهش آن‌ها.
6. برآورد زمان کار به ساعت برای هر مرحله.
7. تجربه مرتبط و نمونه کارهای قبلی.

# ۱۰- محدودیت‌ها و فرض‌ها

- توسعه و آزمون‌های اولیه روی ویندوز ۱۱ با Qt 6.12.0 (MinGW 64-bit) انجام می‌شود.
- هر دستگاه به یک پنجره مانیتور وصل می‌شود.
- مسیر سریال به سخت‌افزار واقعی یا یک جفت درگاه COM مجازی (مثلاً com0com) نیاز دارد.
- در نسخه 0.2.0 حدود هشدار مقادیر پیش‌فرض ثابت دارند.
- هرگز از داده واقعی بیمار استفاده نمی‌شود (بخش ۱-۳).
